# B02 绑定验证码通知投递联动验证

## 范围与调用链

本次只处理 `CHECK-CORE-023` 尚缺的通知投递联动。CodeGraph 与当前源码核对的链路为：`AuthenticationController.sendBindingEmail` → `VerificationCodeServiceImpl.sendBindingEmailCode` → `NotificationService.send` → `NotificationGatewayImpl.enqueue` → `NotificationTaskWorker.processPending` → `MockNotificationProvider.send` → `ntf_delivery`。Web 绑定页沿用 `/api/security/authentication/bind/email` 和原有请求体；OA、Workflow 没有直接调用绑定码入口，其公共通知服务与 Worker 由同一实现提供。

## 修改

- MOCK Provider 只记录渠道、任务 ID、从解密地址重新计算的脱敏收件人和固定结果码；不记录标题、正文或从任务字段复制的收件人掩码。这避免包含六位验证码的投递正文进入应用日志。
- 在现有正式 HTTP 隔离测试中增加渠道不可用、验证码清理、健康检查、入队、Worker 投递、Delivery 唯一记录和重复领取拒绝的联动断言。测试只创建随机合成用户、地址及一次性密钥，结束时清理自身 Redis 键、通知行、Provider 配置和密钥版本。
- MOCK Provider 单元测试覆盖成功日志脱敏，以及配置无效、地址解密失败的阻断分支。
