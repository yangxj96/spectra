# B02 有效 Root 业务范围与写入验证

## 范围

本项续验 `DIAG-CORE-019`、`CHECK-CORE-019` 和 `IMP-CORE-001`。在两个独立应用 JVM 共用正式 Flyway PostgreSQL 测试库和 Redis DB 5 时，合成两个有效 Root、一个仅有 OA 会议读取权限且范围为 SELF 的角色，以及两条合成会议记录。目标 Root 的授权和凭据按数据库时间自然到期，测试在两个进程重复访问业务入口。

有效 Root 时，目标能看到参与和未参与的两场会议，能响应参与的会议，并能暂停和恢复一条合成 Workflow 流程定义。Root 授权到期后，目标仍能登录，但只看得到参与的会议；OA 会议响应、Workflow 流程定义暂停在两个进程均拒绝为 403，数据库参与状态和流程定义活动状态不被拒绝请求改变。凭据到期后，两个进程的相同写请求均为 401。另一有效 Root 始终维持业务读取 200 和最后 Root 停用 409。无身份的后台 `DataScopeExecutor.withoutScope` 调用被拒绝。

合成数据由测试夹具清理。此验证覆盖具体 OA 数据范围、OA 写入及 Workflow 定义写入。Workflow 真实任务的授权到期和后台明确办理人由 `2026-10-19-B02Workflow流程实例通知身份验证.md` 的独立专项覆盖；本项未重新执行这些专项。两个 JVM 运行在同一 Windows 主机，不能作为真实跨主机网络故障的证据。
