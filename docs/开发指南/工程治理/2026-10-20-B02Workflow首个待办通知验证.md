# B02 Workflow 首个待办通知验证

## 范围与影响

本项处理 `DIAG-CORE-034`、`IMP-CORE-007`、`CHECK-CORE-034` 的流程启动入口。CodeGraph 与源码确认：`ProcessInstanceServiceImpl.start` 由 Workflow Controller 与 OA 申请、请假、采购、报销的公共调用方使用。原来只启动 Flowable，待办通知仅在后续任务完成或驳回时触发，首个任务没有通知。

现在流程启动和任务推进共用 `WorkflowTaskTodoNotifier`：对当前活动且有明确办理人的任务，以 `workflow:todo:<taskId>` 为幂等键，使用 `WORKFLOW_TASK` 系统身份解析活跃用户并写入站内信。任务未分配办理人或办理人没有对应活跃用户时跳过待办通知，流程仍可启动。流程启动先在 PostgreSQL 当前事务内按业务键取得 advisory lock，再检查已有运行实例，随后启动并写入首待办；目录或通知命令异常会拒绝启动调用。API `1.0.0` 和 OA/Workflow 调用签名未变。

## 边界

已验证单应用 JVM 中明确办理人且收件人活跃的首个任务、无办理人或无法解析收件人的跳过语义、通知渠道不可用导致的启动回滚和恢复，以及本机两个独立应用 JVM 共享 PostgreSQL/Redis 时相同业务键的竞争。OA 业务回调、跨主机竞争、数据库或 Redis 故障恢复及外部供应商仍未定点验证。`CHECK-CORE-034` 保持 `partially_executed`，B02 保持 `in_progress`。
