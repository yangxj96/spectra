# B02 隔离 Redis 停启恢复验证

## 范围与影响

本项为 `BC-BASE-003`（`DIAG-BASE-007/018`）的 `BC-BASE-003-FAULT-RECOVERY` 补齐**真实 Redis 停启**证据，并支撑 `BC-BASE-002`、`BC-BASE-004`、`CHECK-CORE-022` 中"实际 Redis 停启恢复"的共同缺口。后端 CodeGraph 与源码确认：安全 Redis 连接由 Spring Boot `spring.data.redis.url` 管理，`SecurityRedisExecutor` 在连接或命令失败时抛出 `SecurityRedisUnavailableException` 并保持拒绝。本项没有改动端点、协议或生产源码。

测试启动一个与共享实例隔离的 `redis-server`（独立端口、无持久化），通过 `--spring.data.redis.url` 让被测应用指向它，因而可以安全停止与重启而不影响其他用例；测试结束后由用例自身停止 Redis 进程。

## 可观察行为

1. **正常可用**：隔离 Redis 就绪时，正式登录返回 200。
2. **fail-closed**：停止隔离 Redis 后，携带有效令牌的受保护请求 `/api/security/context` 不再返回 200；登录返回 **503**（应用日志出现 `SecurityRedisUnavailableException: 安全 Redis 不可用`），不降级回源。
3. **恢复**：重启同一端口的隔离 Redis 后，应用重新可用，登录在重试窗口内恢复 200。
