# B02 Session、审计排序与授权公共影响复核

## 范围

本轮按 `IMP-BASE-003`、`IMP-BASE-001`、`IMP-BASE-005`、`IMP-CORE-001` 和 `IMP-CORE-007` 复核当前源码及直接、间接调用方。后端使用 CodeGraph 核对 Session Reader/Refresh/Revocation、Core 主体重载与授权快照、OA/Workflow 审计和分页入口；Web 核对身份失效、审计列表/详情/导出、角色编辑和身份解绑入口。测试仅使用合成数据、专用 PostgreSQL `devops00_spectra_db_test` 与 Redis DB 5，没有读取本机凭据或真实业务数据。

## 实现与安全结论

- `DatabaseSecurityUserLoader` 只把明确的 `LoginException` 视作账号不可用；授权快照或数据库读取的其他异常原样传播，不再伪装为用户不存在。有效本地身份及普通不可用身份行为保持原有语义。
- 旧格式 Session 缺少 Access 或 Refresh 原始截止时间时，当前 Reader/Refresh 路径拒绝，不轮换、不补写缺失字段。部署需通知受影响用户重新登录，不能将旧 Redis 记录解释为可用 Session；真实历史数据没有迁移或清除。
- Redis 撤销发生在数据库事务提交前。合成事务在撤销后回滚时，数据库用户状态仍有效，旧 Access/Refresh 被拒绝，新登录恢复。该窗口的可观察代价是额外重新登录；其余已验证的角色缩权、Assignment、OA/Workflow 写入锁与双 JVM 授权竞争见 B02 先前证据。没有把 Redis 与 PostgreSQL 描述为分布式原子事务。
- OA 成功写入和 Workflow 失败写入的正式 HTTP 审计测试查询 `sys_audit_event`，同时确认事件存在且合成敏感标记未进入快照或原因。统一清洗器的嵌套、自由文本、循环引用等单元测试仍覆盖共同路径。
- Core、OA、Workflow 的排序白名单由同一分页边界处理；54 个入口边界测试和 2 个固定排序调用方测试通过。Web 审计字段与后端 `AuditLogVO` 核对，页面只消费清洗后的 API 数据。

## 尚未验收的边界

- 没有第二台测试主机；真实跨主机网络中断仍按先前明确登记的定点例外处理。同主机两个独立 JVM 的结果不能称为跨主机验证。
- 旧格式 Session 的真实线上滚动部署和历史数据清理没有执行；本轮只用合成旧字段验证失败拒绝。安全停机窗口、通知及强制重新登录属于部署操作，不能以单元测试代替。
- OA/Workflow 全部 `@Audit` 入口的逐入口真实 HTTP 尚未执行；本轮覆盖共同清洗路径及代表性成功、失败入口。Web 浏览器仅用合成 API 响应核对列表和详情消费，未接通后端审计 HTTP。由于本地不启动后端，公开 bootstrap 与通知未读数请求失败，普通点击等待页面稳定性超时，测试使用强制点击；不能据此认定完整浏览器交互已验收。B08 的页面级身份失效也未在此批展开。
- `IMP-BASE-005` 的缓存键碰撞及其他批次的编辑/引用权限、`IMP-CORE-001` 的组织历史语义和 `IMP-CORE-007` 的整体运行态恢复仍属于共享影响项，不能随 B02 的定点检查自动置为 resolved。
