# B02 有效 Root 稳定错误码验证

## 范围与调用方

本项收口 `DIAG-CORE-019` / `CHECK-CORE-019` 的独立 `error_code` 子场景。`RootGovernanceConflictException` 现在分别声明 `ROOT_EFFECTIVE_MINIMUM`、`ROOT_EFFECTIVE_MAXIMUM` 和 `ROOT_POLICY_VERSION_CONFLICT`。Core 在人数下限、人数上限和 Root 策略版本冲突的原有抛出点选择对应枚举；Common 的 `BusinessConflictException` 携带枚举，Framework 的统一异常解析器将其名称写入响应 `error_code`。其他业务冲突仍返回 `BUSINESS_CONFLICT`，HTTP 状态均保持 409，`msg` 仍只作展示。

CodeGraph 与当前源码核对了 Root 事务守卫、策略仓储、统一异常响应和 Web 请求客户端。Web 现有 `HttpRequestError.code` 已读取 `error_code`，相关页面没有按通用 `BUSINESS_CONFLICT` 作业务分支，因此无需迁移 Web 源码。OA/Workflow 没有直接构造 Root 冲突，但共享 Framework HTTP 错误边界；本项没有改动它们的业务入口。正式 API 路径、请求字段和响应包装结构不变。
