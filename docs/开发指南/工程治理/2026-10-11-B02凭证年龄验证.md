# B02 凭证年龄专项验证（DIAG-CORE-022）

## 源码复核与实施

旧台账认定 `SecurityUserAssembler` 只检查显式 `expiresAt`。以当前源码复核后，该判断已不成立：Assembler 已用注入的 UTC `Clock` 同时检查 `expiresAt` 和 `changedAt + maxAgeDays`，在到期边界、缺失或未来 `changedAt`、策略不可用时拒绝认证。校验成功后才组装 `credentialsNonExpired=true` 的主体。密码、邮箱、短信 Provider 和 Session 数据库重载共用这一入口。

本项剩余的代码缺口是凭证写入仍调用 `Instant.now()`。现改为注入的 `Clock`，使首次创建、替换、管理员重置、用户改密的 `changedAt` 与认证侧采用同一可控时间源；重置或改密继续清空旧显式到期、失败次数和锁定状态，并保留 `mustChange` 的现有语义。`LoginExceptionAdvice` 保持 HTTP 401 与既有响应结构，将过期提示传给客户端。未修改 API 版本或 Web 请求与响应字段。

后端 CodeGraph 与当前源码核对：`UserServiceImpl` 的重置和改密调用 `PasswordCredentialService.updatePassword`；用户创建调用 `createOrReplace`；登录 Provider 和 `DatabaseSecurityUserLoader` 调用 Assembler。OA/Workflow 不直接写入密码凭证，经共享认证与 Session 加载间接受影响；全后端编译和静态检查覆盖了两个模块。Web CodeGraph 与当前源码确认登录请求使用 `auth: "skip"`、禁用 401 刷新，错误解析优先采用响应 `msg` 并由请求层展示；到期提示不会被会话失效跳转覆盖。本项未改变响应形状，无 Web 代码改动。
