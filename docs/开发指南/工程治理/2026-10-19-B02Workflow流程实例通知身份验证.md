# B02 Workflow 流程实例通知身份验证

## 范围与调用方

本项核对 `DIAG-CORE-034`、`IMP-CORE-007`、`CHECK-CORE-034` 的 Workflow 流程实例通知调用。CodeGraph 和当前源码显示：`TaskServiceImpl.complete/reject` 在任务动作后调用 `notifyWorkflowResult` 与 `notifyNextTasks`，使用登记的 `WORKFLOW_TASK` 通知系统身份，并按明确办理人登录名解析用户 ID。`ProcessInstanceServiceImpl.start` 负责启动 Flowable 实例。Web 的 `workflow-api.ts` 和 OA 审批中心调用既有 `1.0.0` 任务端点，本项没有改变接口契约或 Web 代码。OA 业务流程回调是另一条调用链，本项未验收。

## 验证边界

已验证单应用 JVM 内的真实 Flowable 和通知持久化。测试直接调用 Service，并设置合成安全上下文；未走 HTTP 认证、活授权快照或数据范围。`TaskServiceImpl` 的直接 Service 入口目前按传入 `operator` 与任务办理人比较，本项不能证明调用者身份与该参数一致，需另项处理。未验证流程启动时首个待办通知、OA 审批业务回调、两个应用 JVM 竞争、Redis/数据库故障恢复及外部通知供应商。`CHECK-CORE-034` 保持 `partially_executed`，B02 保持 `in_progress`。
