# B02 BASE-003 会话撤销 Core 调用方验证

## 范围与结论

本次只处理 `DIAG-BASE-003`。Framework 已在 2026-10-09 将用户会话索引延续至有效 Refresh 生命周期，按用户、客户端和踢旧撤销覆盖 Access 已到期的会话；当时 19 项隔离 Redis 专项通过，但 Core 调用方没有真实 Redis 证据，完整门禁也未通过。本次复核当前源码和调用链后，在 Core 增加四项调用方测试，并重跑后端完整门禁。直接缺陷具备关闭证据；行为检查 `BC-BASE-002` 仍为部分执行。

CodeGraph 从 Framework 撤销端口追到 Core 的用户改密/状态、管理员会话撤销、角色授权、组织和部门变更，再用当前源码搜索核对。测试实际进入 `UserServiceImpl.changePassword` 与 `CacheManagementServiceImpl.revokeSession`，经正式 `SecuritySessionRevocationPort` 适配器和 Framework 实现操作测试 Redis。签发和撤销使用两个独立 Lettuce 连接，测试键有随机前缀，只清理本用例键。角色/组织/部门调用点已纳入影响清单，本次没有逐个执行真实数据库事务或 HTTP 请求。

Web 的 `refreshAccessToken()` 在刷新失败时清理本地会话；本次协议和调用形状没有变化，因此没有改 Web 源码。页面级身份失效和跨标签页行为仍由 B08 验收。OA/Workflow 没有直接调用此撤销端口，共享 Framework 认证边界；八模块门禁覆盖其编译和静态检查，但不证明各业务端到端路径。

## 未验证边界

Core 测试使用真实服务方法和 Redis，但持久化与审计协作者为模拟对象；真实 HTTP、数据库事务和安全版本变更后的完整调用链尚未执行。两个独立 Redis 连接不等于两个独立应用进程，真实 Redis 停启及故障恢复也没有运行。`RegionServiceTest` 在完整门禁中显式排除。Web 浏览器身份失效归 B08。故 `BC-BASE-002-CORE-CALLERS` 仅部分执行，`BC-BASE-002-TWO-PROCESSES` 未运行，`IMP-BASE-003` 与 B02 保持 `in_progress`。
