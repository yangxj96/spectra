# B02 CORE-019 有效 Root 正式 HTTP 验证

## 本次范围与调用影响

`RootGovernanceFullHttpTest` 使用完整 Spring Boot 应用、正式 Flyway schema、Core 用户 Controller/Service、MyBatis Mapper、PostgreSQL 和 Redis Session，覆盖用户停用和 Web 实际使用的用户编辑撤销角色入口。测试只插入随机合成部门、用户、密码凭据、登录身份及 `ROLE_DEV_OPS` Assignment；撤权夹具还经正式服务补齐 `ROLE_USER` 及其 Boundary。运行前检查数据库为 `devops00_spectra_db_test`、Redis 为 DB 5，并要求已有有效 Root 人数为零。并发阶段暂将测试库 Root 策略下限从 1 设为 2，`finally` 恢复为 1；结束时清理本次合成部门、用户、授权边界、Scope 与会话。正式审计链生成的合成审计记录保留在可重建的专用测试库内。

当前 CodeGraph 和源码核对了两条路径：`/api/user/disable/{uid}` → `UserController.disable` → `UserServiceImpl.changeStatus`，以及 Web `RoleAssignmentEditor` 的 `removed_assignments` → `UserApi.submitUpdate` → `PUT /api/user/onboarding` → `UserOnboardingServiceImpl.submitAuthorization` → `AuthorizationAssignmentChangeServiceSupport.revoke`。两条路径均通过 `JdbcLastEffectiveDevOpsGuard`、正式 Mapper 和 `SecuritySessionRevocationPort`。Core 生命周期其他状态、身份、凭据、策略及首次初始化还有各自的 Root 守卫入口。OA/Workflow 没有直接调用本次两个写入口，其公共身份与授权读取仍是间接影响。本次没有修改 API 1.0.0 路径、请求或响应协议，也没有 Web 代码迁移。

专项中的初始单 Root 自我停用返回 HTTP 409，响应 `code=409`，数据库仍为 `ACTIVE`，有效 Root 人数仍为 1，旧 Access 仍可访问。新增两名 Root 后，在下限 2 的并发停用中，一次返回 200、一次返回 409；成功目标变为 `DISABLED` 且旧 Access 返回 401，失败目标保持 `ACTIVE` 且旧 Access 返回 200。恢复下限 1 后停用剩余目标成功，人数降为 1；再次停用最后 Root 返回 409，操作者状态和 Session 保留。该路径实际覆盖正式 Root 计数 SQL、事务行锁、HTTP 冲突映射和 Redis Session 撤销副作用。

新增的用户编辑撤权专项从三名有基础角色的合成 Root 出发，在下限 2 并发移除两名目标的 `ROLE_DEV_OPS` Assignment：一次 HTTP 200、一次 409，人数保留 2；成功目标 Assignment 为 `REVOKED`、旧 Access 401，失败目标 Assignment 为 `ACTIVE`、旧 Access 200。恢复下限 1 后移除剩余目标成功且其旧 Access 401；再次移除最后 Root 返回 409、`code=409`，Assignment 仍 `ACTIVE`，操作者旧 Access 仍可访问。测试经用户资料、部门关系、RoleAssignment、审计、Root 策略锁及正式 Redis Session 全链路，覆盖 Web 当前发送的 `removed_assignments` 请求形状。缺少基础角色的合成夹具曾在拒绝撤权前被自动补角色并撤销旧会话，因此当轮夹具通过正式服务先补齐基础角色；这一异常初始状态随后在 [[开发指南/工程治理/2026-10-13-B02有效Root基础角色撤权副作用验证|2026-10-13 基础角色撤权副作用专项]]中修复并补验。

## 验证边界

本项覆盖用户停用和用户编辑撤销角色的完整 HTTP 路径。身份解绑、凭据及策略变更、首次初始化的正式 HTTP 路径，以及两个独立应用进程下的 Root 变更和授权/凭据随时间自然失效仍待验证；OA/Workflow 的间接业务入口和 Web 浏览器路径也未运行。现有统一失败响应只有 HTTP 状态与 `code=409`，没有独立 `error_code` 字段；稳定业务错误码属于待统一的协议工作，不能以本测试宣称通过。完整门禁显式排除已单独通过的四个完整应用 HTTP 专项及既有 `RegionServiceTest`；固定测试库的 Root 最小表与正式 Flyway schema 分段运行。`CHECK-CORE-019` 仍为部分执行，`IMP-CORE-001` 仍为待验收，B02 保持 `in_progress`。
