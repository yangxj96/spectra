# B02 CORE-019 有效 Root 正式 HTTP 验证

## 本次范围与调用影响

`RootGovernanceFullHttpTest` 使用完整 Spring Boot 应用、正式 Flyway schema、Core 用户 Controller/Service、MyBatis Mapper、PostgreSQL 和 Redis Session，补上先前受控 Mapper 测试未覆盖的用户停用入口。测试仅插入随机合成用户、密码凭据、登录身份及 `ROLE_DEV_OPS` Assignment；运行前检查数据库为 `devops00_spectra_db_test`、Redis 为 DB 5，并要求已有有效 Root 人数为零。并发阶段暂将测试库 Root 策略下限从 1 设为 2，`finally` 恢复为 1；结束时只清理本次随机用户与会话。

当前 CodeGraph 和源码核对的路径为 `/api/user/disable/{uid}` → `UserController.disable` → `UserServiceImpl.changeStatus` → `JdbcLastEffectiveDevOpsGuard` → `JdbcRootPolicyRepository`，成功路径还经 `SecuritySessionRevocationPort` 撤销 Redis Session。Core 生命周期的锁定、解锁、启用、离职和重新入职均共用 `changeStatus`；授权、身份、凭据、策略及首次初始化有各自的 Root 守卫入口。OA/Workflow 未直接调用用户生命周期变更，公共身份与授权读取仍是间接影响。Web `UserApi` 当前没有该生命周期操作的直接包装调用方；本次未改变路径、请求或响应协议，也没有 Web 代码迁移。

专项中的初始单 Root 自我停用返回 HTTP 409，响应 `code=409`，数据库仍为 `ACTIVE`，有效 Root 人数仍为 1，旧 Access 仍可访问。新增两名 Root 后，在下限 2 的并发停用中，一次返回 200、一次返回 409；成功目标变为 `DISABLED` 且旧 Access 返回 401，失败目标保持 `ACTIVE` 且旧 Access 返回 200。恢复下限 1 后停用剩余目标成功，人数降为 1；再次停用最后 Root 返回 409，操作者状态和 Session 保留。该路径实际覆盖正式 Root 计数 SQL、事务行锁、HTTP 冲突映射和 Redis Session 撤销副作用。

## 验证边界

本项只覆盖用户停用的完整 HTTP 路径。授权撤销、身份解绑、凭据及策略变更、首次初始化的正式 HTTP 路径，以及两个独立应用进程下的 Root 变更和授权/凭据随时间自然失效仍待验证；OA/Workflow 的间接业务入口和 Web 浏览器路径也未运行。现有统一失败响应只有 HTTP 状态与 `code=409`，没有独立 `error_code` 字段；稳定业务错误码属于待统一的协议工作，不能以本测试宣称通过。完整门禁显式排除已单独通过的四个完整应用 HTTP 专项及既有 `RegionServiceTest`。`CHECK-CORE-019` 仍为部分执行，`IMP-CORE-001` 仍为待验收，B02 保持 `in_progress`。
