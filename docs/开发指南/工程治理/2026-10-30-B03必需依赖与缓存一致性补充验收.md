## 1. 本阶段实现

### 1.1 缓存一致性恢复校验

- 新增 `CacheConsistencyVerifier`，在依赖恢复后通过专用业务缓存键执行写入、读取和清理，验证缓存命令、键前缀和受控序列化器均可用。
- 校验业务缓存命名空间不得与安全 Redis 固定命名空间 `sec:` 重叠。
- 业务缓存仍为派生数据；Redis 重启后允许为空并从数据库重建，不尝试复原历史缓存。
- 校验失败时抛出异常，`DependencyReadinessProbe` 保持 `UNREADY` 并继续退避，不恢复业务。

### 1.2 后台任务暂停兜底

- `DependencyReadinessProbe` 在 `pauseAll()` 因数据库故障失败时改用 `Scheduler.standby()`；恢复时先 `start()` 再 `resumeAll()`。
- 避免数据库故障期间后台调度暂停因依赖不可用而完全失效。

### 1.3 验证入口补强

- 新增 `DatabaseOutageHttpTest`：使用本地 TCP 代理和正式 HTTP 验证数据库运行故障时业务 503、进程保留、恢复后重新进入认证流程。
- 新增 `DatabaseStartupFailClosedTest`：验证数据库不可达时启动失败。
- `ReadinessGateHttpTest` 增加缓存一致性校验器 Bean 断言。
- 双进程测试改用 Java 参数文件启动第二应用，避开 Windows 命令行长度上限。
