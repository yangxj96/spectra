# B02 双进程会话策略收紧验证

## 范围与影响

本项为 `CHECK-CORE-019`（`DIAG-CORE-019`）补齐**正式 HTTP 会话策略收紧跨两个应用进程传播**的证据：一个进程修改 Web 会话策略后，另一进程用旧 Access 访问立即被拒绝。后端 CodeGraph 与源码确认：`SecurityPolicyController.modifySessionPolicy` 更新 `sec_session_policy` 并提升版本，Framework 每次读取会话时通过 Core 的 `SecuritySessionPolicyProvider` 从 PostgreSQL 读取当前策略判定 `SecuritySessionLifetime.expired`；两个应用 JVM 共享同一 PostgreSQL 与 Redis DB 5。本项没有改动端点、协议或生产源码，在 `CoreTwoProcessHttpTest` 增加第三个两进程用例。

## 可观察行为

1. **策略写入**：首进程运维用户经 `/api/security/policy/session/{clientId}` 会话策略接口把 Web `absolute_ttl_seconds` 收紧为 1，接口返回 200。
2. **跨进程传播**：等待 2 秒后，第二进程用收紧前签发的目标用户 Access 访问 `/api/security/context` 返回 401，证明策略由共享数据库在另一进程生效。
3. 用例结束按原始策略值恢复专用库 Web 策略并撤销合成会话（恢复使用 JDBC，避免收紧策略影响运维会话）。
