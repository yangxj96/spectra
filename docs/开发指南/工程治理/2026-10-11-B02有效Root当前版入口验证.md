# B02 CORE-019 有效 Root 当前版入口验证

## 本次复核与处置

2026-10-10 的 [[2026-10-10-B02有效Root保护验证|首轮证据]]已覆盖用户状态、授权、身份、凭据与策略变更，并用合成 PostgreSQL 验证计数、回滚和竞争。当前源码复核补出两个缺口：首次系统初始化 `complete` 会直接激活用户并写入 `ROLE_DEV_OPS` Assignment，却未经过 Root 策略行锁和写后人数复核；`JdbcRootPolicyRepository` 将无法确认的 `null` 人数当作 0，策略锁查询返回 `null` 也未立即拒绝。

初始化完成现在在验证初始化状态后锁定 Root 策略行、记录变更前人数，在激活用户及写入 Assignment 后复核上下限，随后才运行其他完成步骤。策略或人数查询无法确认时抛 `RootGovernanceException`。已有公共写入服务继续共用该守卫；初始化阶段仍保留原有初始化事务和 PostgreSQL advisory lock。

CodeGraph 与精确调用搜索核对了 Core 用户生命周期、RoleAssignment、认证身份、密码凭据、密码策略和首次初始化入口。OA/Workflow 没有直接调用上述 Root 变更服务，仍通过公共授权身份间接受影响。Web `SystemInitializationApi.complete` 继续使用原路径和请求体；初始化页只在成功后切换为已初始化并跳转登录，失败时留在当前步骤，由请求层显示错误。本次没有 API 1.0.0 协议变化或 Web 代码迁移。
