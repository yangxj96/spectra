# B02 会议分页业务入口验证

## 单项范围

本单项接续 BC-BASE-008 的 OA 正式 Mapper 验证，聚焦会议分页。CodeGraph 与当前源码确认调用链为 `MeetingController.page` → `MeetingServiceImpl.page` → 继承的 `MeetingMapper.selectPage`；Web 的 `MeetingApi.page` 和会议列表页面是调用方，协议未修改。采购收货、资产入库、Core、Workflow 没有本次代码变更，但仍受 Framework 公共数据范围能力的间接影响。

新增 `OaMeetingPageHttpPostgresTest`，在专用 PostgreSQL `devops00_spectra_db_test` 内以随机 UUID 合成会议及参与人，使用实际会议 Service、MapStruct 转换器、Mapper、数据范围拦截器、分页插件和会议 Controller；Spring MVC standalone MockMvc 装配项目统一异常处理器及与生产一致的默认 API 版本策略。测试事务回滚，不读取或输出本机凭据。测试入口先限制 `DB_URL` 的库名，阻止在其他数据库执行。

成功路径验证参与人可见会议的分页记录和总数均为 1，无关会议不出现在响应；移除授权快照后列表及总数均为 0。失败与恢复路径验证恶意排序字段返回安全的 HTTP 400 且响应不回显原字段，随后允许字段的查询仍返回 HTTP 200 和正确总数。该测试使用最小合成 OA 表结构；它验证当前 Service/MVC/SQL 组合，没有运行完整应用安全过滤器或正式 Flyway schema。

## 边界与后续

本次覆盖正式会议 Controller 的 MVC 参数绑定及响应、Service 分页、实际 PostgreSQL Mapper、分页计数和关系范围，并验证失败后可继续查询。standalone MockMvc 不运行完整 Spring Boot 过滤器、安全授权、审计和加密链；表结构为测试事务内的最小合成结构，尚未核对正式 Flyway schema 或全部分页入口。采购详情/资产入库 Service、浏览器、双应用进程以及真实故障恢复仍未执行。BC-BASE-008 与 B02 保持未验收；`RegionServiceTest` 在完整门禁中显式排除。
