# B02 策略与首次初始化正式 HTTP 验证

## 范围与调用方

本项补 `DIAG-CORE-019`、`CHECK-CORE-019` 的密码策略与首次初始化正式 HTTP 入口，同时核对 `IMP-CORE-001` 和安全策略版本冲突的直接影响。后端 CodeGraph 与当前源码确认：`SecurityPolicyController` 的密码策略写入经 `JdbcSecurityPolicyService`、Root 策略锁、有效人数复核和安全审计；`SystemInitializationController` 的 `start/complete` 经 PostgreSQL 初始化锁、状态行锁、首次 Root 激活与授权写入。Web 的初始化页调用 `/system/initialization/status|start|complete`，个人改密页读取 `/security/policy/password`；OA/Workflow 没有直接策略或初始化写入调用，仍共享认证和授权状态。路径、请求字段及 Web 调用形状未变，本项没有改动 Web、OA、Workflow 源码。

环境为原生 Windows PowerShell、mise test、JDK 25、后端 Maven Wrapper、专用 PostgreSQL `devops00_spectra_db_test` 与 Redis DB 5。测试只生成合成账号、密码、一次性初始化令牌和角色状态；不读取或输出本机凭据。完整初始化会创建合成系统设置与内部密钥，因此用限定测试库名、确认无其他连接的 `RecreateTestDatabase.java` 在专项后重建测试库。测试主动撤销合成用户的 Redis Session 并清理初始化令牌摘要；最后由 Root HTTP 单项重新运行正式 Flyway schema。

## 实现与行为

密码策略正式 HTTP 首次验证表明：收紧 `max_age_days` 使最后有效 Root 失效时返回 409，事务回滚且策略版本不变；增加另一个有效 Root 后同一调整成功，过龄用户旧 Access 返回 401。两个请求携带相同策略版本并发更新时，只有一个成功。首轮测试在此处失败：版本冲突没有返回 409。`JdbcSecurityPolicyService` 现在把密码和会话策略的预检查或更新版本冲突抛为 `BusinessConflictException`；增加会话策略过期版本 HTTP 断言，确认同一映射的直接影响。

首次初始化正式 HTTP 验证无效令牌拒绝，两个并发 `start` 仅一次成功，错误初始化 ID 不激活 Root，两个并发 `complete` 仅一次成功；成功后系统状态为 `INITIALIZED`、首个 `ROLE_DEV_OPS` 有效人数为 1、合成账号可登录、Redis 初始化令牌摘要已清除。测试启动时压低初始化令牌管理器的日志级别，日志未出现一次性令牌文本。该用例使用完整应用、正式 Flyway schema、实际 PostgreSQL/Redis、Controller、Service、Mapper 和安全链；初始化成功后的数据库状态通过专用库重建恢复。
