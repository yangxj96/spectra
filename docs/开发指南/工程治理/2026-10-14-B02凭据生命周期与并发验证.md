# B02 凭据生命周期与并发验证

## 范围与环境

本项处理 `DIAG-CORE-019` 的凭据变更入口和 `DIAG-CORE-022` 的真实凭据年龄、重置与改密链路，对照 `IMP-CORE-001`、`IMP-CORE-005` 和会话影响 `IMP-BASE-003`。使用原生 Windows PowerShell、mise test、后端 Maven Wrapper、专用 PostgreSQL `devops00_spectra_db_test` 和 Redis DB 5。测试只创建随机合成用户、身份、密码及角色；没有读取或输出本机凭据。固定测试库的 Root 最小表测试与正式 Flyway schema 分段执行。

CodeGraph 与当前源码复核确认密码写入直接调用方在 Core：用户新建、管理员重置、本人改密和首次初始化；Web 个人中心调用 `PUT /api/user/password`，管理端重置调用 `PUT /api/user/password/reset/{uid}`。OA/Workflow 没有直接密码写入调用方，但共用登录、授权和 Session 状态。本项没有改动接口路径或请求字段，Web 与暂缓业务代码无需同步修改。

## 修复与行为证据

`UserServiceImpl.changePassword` 原先在读取并验证旧密码后才由凭据服务取得 Root 策略行锁。两个请求可在锁外同时通过同一个旧密码校验，之后依次写入不同新密码。现于读取凭据前获取同一事务锁，校验和更新位于统一序列化边界。两个有效 Root 同时将凭据写成已过期时，凭据服务的 Root 下限复核只准一次提交。

`TokenAuthenticationFilter` 原先对必须改密的其他请求调用 `sendError(403)`，正式 HTTP 实际经过错误分派返回 401。现直接写统一 JSON 403 和 `请先修改密码` 提示，允许的密码规则、客户端私钥、改密与退出入口维持原有准入。凭据年龄到期的密码登录仍返回 401。

正式完整应用 HTTP 测试使用 Flyway schema、真实 PostgreSQL 和 Redis Session：年龄策略收紧及时间超龄后，旧 Access 与旧密码登录均返回 401；管理员使用专用库中临时配置的合成默认密码重置，目标用户旧 Access 保持失效，新登录只可完成改密，访问安全上下文返回 JSON 403；改密后重置 Session 失效，新密码重新登录恢复，`must_change` 清除。测试结束仅在配置仍为本项临时哈希时还原空配置，并清理合成用户及 Session。

并发测试先独占 PostgreSQL Root 策略行，确认两个正式 HTTP 改密请求均等待该锁后放行。修复前两个请求都成功，测试以 `expected: <1> but was: <2>` 退出 1；修复后仅一个成功，另一个因旧密码失效拒绝，旧 Session 401，只有已提交的新密码可登录。另用两个线程对两个有效 Root 写入过期凭据，仅一次提交且有效 Root 保持 1。`RootGovernanceFullHttpTest` 整组 8/8（6 项正式 HTTP、2 项直接服务竞争）通过。每个完整 HTTP 夹具只删除专用 Redis DB 5 中回环 IP 当前一分钟的登录限流键，避免整组测试互相消耗 10 次登录额度；生产限流规则及其他安全键未改。
