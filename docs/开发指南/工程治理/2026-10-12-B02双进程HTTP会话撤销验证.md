# B02 双进程 HTTP 会话撤销验证

## 范围与调用方

本单项核对 `BC-BASE-002-TWO-PROCESSES` 和 `IMP-BASE-003` 的共享 Session 撤销。CodeGraph 与当前源码确认，Core 的 Assignment Apply/Revoke、Role Authorization Apply、用户状态和改密等入口经 `SecuritySessionRevocationPort` 到 Framework 的 `SecuritySessionRevocationService`；认证登出则经 `AuthenticationController`、`LoginService` 和相同的安全 Redis 会话能力。OA/Workflow 没有直接调用本次端口，仍通过公共授权与身份能力间接受影响。Web `AuthApi.logout` 使用现有登出路径，请求层的 Refresh 失败处理会清理本地 Session；本单项没有修改协议或 Web 代码。

新增 `SessionTwoProcessHttpTest`，在两个独立 JVM 中各启动一份完整 Spring Boot 应用。首个进程由 Maven Surefire 承载，第二个由测试启动的 Java 子进程承载；两者通过各自的 Spring 容器访问同一专用 PostgreSQL 和 Redis DB 5，进程 ID 不同。两个实例的用户加载器与授权快照由仅在测试属性启用的合成提供者提供，并通过随机 UUID 指向同一合成用户；Session 签发、Redis 存取、Servlet 安全过滤器、Core 正式 HTTP 登出和授权上下文接口为正式实现。两个实例不共享测试进程内的身份或会话内存。

场景依次验证：匿名请求在第二进程返回 HTTP 401；首进程签发的 Access 在第二进程返回 200；首进程正式 `POST /api/security/authentication/logout` 返回 200 后，旧 Access 在两个进程均返回 401；新签发的 Access 在第二进程返回 200；首进程经 Core 公共撤销端口按用户撤销后，两个进程均拒绝旧 Access；再次签发后第二进程恢复 200。令牌原文仅保存在测试进程内，不写入报告或命令行。测试入口校验 `DB_URL` 仅指向 `devops00_spectra_db_test` 且 `REDIS_DB=5`。

## 验证边界

这项证据只关闭两个独立应用进程之间的 Access 会话共享、正式 HTTP 登出与公共按用户撤销的交叉验证。Core 身份、角色与授权快照由合成夹具代替；正式 Core HTTP 登录、Role Assignment/Role Authorization 数据库事务与重登录后权限收缩、Access 自然过期时的 Refresh 撤销、真实 Redis 停启恢复及 Web 浏览器身份失效均未由本场景验证。现有隔离 Redis/服务测试覆盖部分 Refresh 生命周期，但不能代替这些入口。八模块门禁为分段验证：固定测试库中的 Root 最小表夹具与正式 Flyway schema 不能同轮共存，因此门禁排除了已单独通过的完整应用会议 HTTP 与本次双进程 HTTP 专项；`RegionServiceTest` 仍按既有已登记边界显式排除。`BC-BASE-002`、`IMP-BASE-003` 和 B02 继续未验收。
