# B02 登录桶与验证码预算双进程验证

## 范围与影响

本项为 `CHECK-CORE-020`（`DIAG-CORE-020`）与 `CHECK-CORE-023`（`DIAG-CORE-023`）补齐**两个独立应用进程共享 Redis** 的证据：登录失败身份桶与绑定验证码尝试预算都跨进程共享，一个进程的失败会累计到另一个进程并使后续正确凭据被拒绝。后端 CodeGraph 与源码确认：`LoginServiceImpl` 与 `AuthenticationIdentityBindingServiceImpl` 都通过共享安全 Redis 的计数/尝试键读写，两个应用 JVM 各持自己的上下文但读写同一 Redis DB 5。本项没有改动端点、协议或生产源码。

## 可观察行为

1. **登录失败桶跨进程共享**：目标用户在首进程失败 `lockoutMaxAttempts-1` 次、在第二进程再失败 1 次后，首进程用正确口令登录返回 401（已锁定），证明变体/失败被归并到同一共享身份桶。
2. **绑定验证码预算跨进程共享**：为目标用户播种绑定验证码后，首进程错误尝试 `verificationCodeMaxAttempts-1` 次、第二进程再尝试 1 次即达上限，验证码键被原子删除；随后即使提交正确验证码也返回 400。
