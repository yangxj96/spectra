# B02 受控发送 Service 权限边界验证

## 范围与实现

本项补 `CHECK-CORE-034` 的受控发送 Service 直接调用边界。CodeGraph 核对：Web 通知发送页只经 `NotificationControlledSendApi` 调用 `1.0.0` 的 Preview/Apply Controller；OA、Workflow 后台通知走公共通知端口，不调用受控发送 Service。Controller 已分别检查 `notification:send:preview` 和 `notification:send:apply`，但原 Service 只读当前用户 ID。工程标准要求 Service 自身是最终业务授权边界。

`NotificationControlledSendServiceImpl` 现在在读取模板、Preview 或创建通知之前，通过 `AuthorizationSnapshotProvider.load(operatorId)` 读取操作人的当前有效授权快照。Preview 和 Apply 分别要求对应操作权限；无身份、快照为空或缺权限时抛出 `AccessDeniedException`，快照读取异常继续拒绝，不把未知状态当作授权。受众数据范围和 Preview 操作人绑定仍由既有路径执行。

## 验证边界

真实数据库角色到期验证在同一应用进程内完成，直接调用采用合成的当前用户上下文；跨实例受控发送竞争和角色变更与正在执行的 Apply 同时竞争未运行。此前 HTTP 用例的错误 token 被拒绝，但观察到既有异常映射返回 500；本项没有改变该错误契约，需另行处理。OA 合同 Quartz、Workflow 实例和外部 Provider 仍未验收。`CHECK-CORE-034` 与 B02 均维持进行中。
