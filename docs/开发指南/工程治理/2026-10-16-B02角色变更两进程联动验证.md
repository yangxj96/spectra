# B02 角色变更两进程联动验证

## 范围与影响

本项为 `CHECK-CORE-032`（`DIAG-CORE-032`）补齐**角色变更跨两个应用进程**的证据：一个进程缩权后，另一进程的旧会话被撤销，重新登录快照反映收缩。后端 CodeGraph 与源码确认：角色授权 Apply 在业务事务内更新 Role 权限与 Assignment Boundary/Scope，并提升 Role 版本与目标用户 `security_version`、撤销目标用户 Redis Session；两个应用 JVM 共享同一 PostgreSQL 与 Redis DB 5。本项没有改动端点、协议或生产源码，在既有 `RoleAuthorizationFullHttpTest` 内新增两进程用例并复用其夹具与授权变更 token 配置。

## 可观察行为

1. **跨进程会话可见**：目标用户在第二进程登录的 Access 在首进程 `/api/security/context` 返回 200。
2. **缩权跨进程撤销**：首进程完成角色 impact-preview 与 impact-apply 缩权（移除 `role:grant`）后，第二进程用旧 Access 访问 `/api/security/context` 返回 401。
3. **重登录快照收缩**：目标用户在第二进程重新登录后，上下文仍含 `role:read`、不含 `role:grant`。
