# B02 有效 Root 自然失效验证

## 场景与调用方

本项补充 `DIAG-CORE-019` / `CHECK-CORE-019` 的时间自然流逝场景。正式应用在专用 PostgreSQL 和 Redis 上创建两个合成 Root，并分别登录。一个 Root 的 `sec_role_assignment.valid_until` 先设为数据库当前时间后 4 秒；其到期前仍计入有效人数，到期后有效人数从 2 降为 1，旧 Access 仍能识别主体，但调用 `/api/user/disable/{id}` 失去 Root 权限而返回 403。剩余 Root 试图停用自身返回 409 / `ROOT_EFFECTIVE_MINIMUM`，状态保持 ACTIVE。

测试随后仅恢复合成授权，再将同一用户的 `sec_password_credential.expires_at` 设为数据库当前时间后 4 秒。到期前有效人数为 2、旧 Access 可用；到期后人数降为 1、旧 Access 和密码重新登录均返回 401，剩余 Root 的停用仍返回 409，状态不变。等待条件按 PostgreSQL 实际计数轮询，不移动生产时钟，也不使用真实业务数据。

CodeGraph 与当前源码核对了 `JdbcRootPolicyRepository.countEffectiveDevOpsUsers`、`SecuritySessionReaderService`、`DatabaseSecurityUserLoader`、`SecurityUserAssembler` 和授权快照加载器。有效 Root 计数使用数据库 `statement_timestamp()`；Session 读取重新加载用户，凭据到期拒绝身份，授权到期从快照中移除角色。Web 现有 Session 与错误响应协议未改变；OA/Workflow 无此测试直接调用，间接业务入口保留待验收。

两个独立应用 JVM 的追加场景复用同一专用 PostgreSQL/Redis：第一进程登录运维 Root、第二进程登录待到期 Root，双方先接受同一个 Access。待到期授权写入数据库时间后 5 秒，过期后两个进程均保持用户认证 200，但用旧 Access 停用其他用户均返回 403；第一进程用剩余 Root 停用自身返回 409。仅恢复合成授权后，将凭据显式到期设为数据库时间后 5 秒；到期后两进程旧 Access 都返回 401，第二进程旧 Refresh 返回 401，第二进程中剩余 Root 的停用仍为 409。两个应用 PID 不同，状态通过共享依赖传播，没有进程间测试私有内存通道。

## 验收边界

本项覆盖单进程和两个独立应用 JVM 中授权关系与密码凭据按真实时间自然到期，以及到期后的授权、认证与最后 Root 保护。未覆盖实际 Redis 停启、初始化及策略故障恢复、OA/Workflow 间接业务入口和 B08 浏览器路径。`CHECK-CORE-019` 仍为 `partially_executed`，B02 仍为 `in_progress`。
