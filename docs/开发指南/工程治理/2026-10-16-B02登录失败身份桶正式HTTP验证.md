# B02 登录失败身份桶正式 HTTP 验证

## 范围与影响

本项为 `CHECK-CORE-020`（`DIAG-CORE-020`）补齐**真实 HTTP** 证据：登录失败计数按 `AuthenticationIdentifierHash.digest`（trim + 小写）归并到同一身份桶，大小写/空白变体不再分散猜测计数；达到阈值后同一账号被锁定；成功登录清理同一身份桶。后端 CodeGraph 与源码确认：`LoginServiceImpl.login` 先用规范化摘要检查 `isLockedOut`，失败时 `recordLoginFail(identityBucket)`，成功时 `clearLoginFail(identityBucket)`；`LoginException` 继承 `BadCredentialsException`，未知账号与错误密码都计入同一桶。本项没有改动端点、响应字段或生产源码，因此未改动 Web、OA、Workflow。

测试通过正式 `/api/security/authentication/login` 端点，在专用 PostgreSQL/Redis 上插入真实 PASSWORD 身份与凭据；为排除按 IP 的登录请求限流（10 次/分钟）干扰，用例在每次请求前清除本机当前窗口的限流键。

## 可观察行为

1. **变体归并**：对同一账号连续使用大写、前后带空白的用户名变体提交错误密码，失败计数累计到规范化身份桶；达到 `lockoutMaxAttempts`（默认 5）后，桶计数等于阈值。
2. **锁定时拒绝**：达到阈值后，用**正确**密码登录仍返回 401（`账号已锁定，请稍后再试`），拒绝先于密码校验。
3. **成功清理**：另一账号在少量失败后使用正确密码登录返回 200，同一身份桶计数回到 0。
4. **运维端口定向清理**：目标账号达到锁定阈值后，运维用户经 `/api/cache/admin/security/login-failure/clear`（`username` + 理由 + `confirmed`）清理同一身份桶，桶计数回到 0，随后目标账号用正确密码登录返回 200。
