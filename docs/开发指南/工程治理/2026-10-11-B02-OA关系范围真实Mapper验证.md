# B02 OA 关系范围真实 Mapper 验证

## 范围与调用链

本单项接续 `BC-BASE-008-SCOPE` 的策略层验证，针对 OA 正式 `MeetingMapper` 与 `PurchaseReceiptMapper` 补充 PostgreSQL 上的 Mapper 执行证据。CodeGraph 和当前源码确认：`MeetingController.page` 经 `MeetingServiceImpl.page` 使用继承的会议 Mapper 分页查询；`PurchaseServiceImpl` 在采购详情中调用 `PurchaseReceiptMapper.selectList`，`AssetServiceImpl` 还通过该 Mapper 按 ID 核对收货单。Web 的 `MeetingApi.page` 与会议列表页面是后续 HTTP/页面验证入口；采购收货又影响采购详情与资产入库。两类 Mapper 共用 Framework 的 `DataPermissionInterceptor`、`DataScopeInnerInterceptor` 和授权快照。Core 与 Workflow 没有直接声明本次两张 OA 关系表，仍是该公共拦截器的间接调用方；本单项没有修改其生产调用或 Web 协议。

在 `spectra-launch` 测试层装配 OA 正式 Mapper、真实数据范围注册表和与正式配置一致的 UUID TypeHandler。专用 PostgreSQL 测试库中，以一个 JDBC 事务创建缺失的最小 OA 表并写入随机 UUID 合成记录；如表已存在，仅写入合成记录。测试结束强制回滚，不使用真实业务数据，也不读取或输出本机凭据。测试入口先校验 `DB_URL` 只指向 `devops00_spectra_db_test`。

会议测试覆盖参与人可见、无关会议不可见、同一范围下 `selectCount` 与列表一致、撤去授权后列表和计数都为零。采购收货测试覆盖授权采购部门可见、切换授权 Boundary 后只见另一部门收货单、无授权时拒绝。实体 `selectList` 和 UUID 主键映射均实际执行。关系部门分支按已登记的 Assignment Boundary 判定，用户成员集合仅约束结构部门分支；此处沿用现有语义，没有扩大范围策略。

环境：原生 Windows PowerShell 7.6.6、mise 2026.10.4、Temurin 25.0.2+10、Maven Wrapper 3.9.12；在 `spectra-admin/` 运行 `mise -E test exec --`，使用私有 test 环境、PostgreSQL `devops00_spectra_db_test`，完整门禁中的 Redis 用例使用 DB 5。

## 验证边界

该证据证明 OA 两个正式 Mapper 在真实 PostgreSQL 上执行了受范围约束的 `selectList`，会议 Mapper 还执行了 `selectCount`。它不覆盖会议/采购的完整 Service 事务、正式 HTTP 分页和详情响应、业务 schema 全量迁移、浏览器或双应用进程；`BC-BASE-008` 仍为部分执行，B02 不因此验收。`RegionServiceTest` 在完整门禁中显式排除。
