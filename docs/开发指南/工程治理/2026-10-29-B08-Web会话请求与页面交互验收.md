## 1. 本阶段实现

### 1.1 请求与会话代数

- `request-lifecycle.ts` 维护会话代数；登录、退出和会话失效递增代数，同时取消在途请求、清空去重登记和缓存。
- 缓存键、去重键和请求键包含会话代数，旧身份响应不能命中新会话；旧刷新结果按发起代数校验，不能覆盖新登录 Token，也不能清理新会话。
- Fetch 与 XHR 的 401 处理先核对代数和认证方式；迟到 401 转换为取消错误，不触发全局过期提示。
- 重试改为独立尝试循环：每次尝试重新加密请求体、创建控制器并释放优先级；只有安全方法或显式声明 `idempotent` 的写入、且错误可分类重试时才重试，受整体截止时间约束。
- 请求层默认不再展示全局遮罩；`useTable`、页面和按钮负责局部 loading。同一 Error 对象只提示一次，请求层与页面 catch 不会重复弹窗。

### 1.2 Store 会话范围

- 新增 `session-scope.ts` 注册集中清理：用户 Token、应用菜单/授权路由/引导状态、通知列表与未读数、字典缓存与错误、加密配置和客户端私钥。
- 通知 Store 和字典 Store 增加会话世代；身份切换后旧查询结果不能回填。
- 字典加载失败不再返回空数组伪装成功：记录错误、抛出 `DictLoadError`，选择器和标签显示失败状态并允许重试。

### 1.3 Hook 与组件

- `useTable` 接收参数对象或 Ref，每次查询解析最新条件；使用查询序号和卸载标记保护写回，暴露局部 `loading`。
- `JsonEditor` 在卸载时取消防抖、销毁编辑器；提供 `flush()` 供提交前同步输入。
- `RegionSelectLazy` 清空时同步清理 id、名称和路径；异步路径响应按世代校验，加载失败显示可重试错误。
- loading 关闭任务可取消并核对实例与引用计数，新请求不会被旧关闭定时器误关。
- `OAApproverSelect` 远程查询增加序号和卸载保护。

### 1.4 页面编辑、预览与提交

- 部门合并/拆分预览按输入世代丢弃迟到响应，确认和提交捕获同一不可变预览对象。
- 用户编辑的授权编辑器改为保持挂载，返回基本信息再进入不会重建草稿。
- 授权方案、角色和通知模板保存识别 HTTP 409，保留当前草稿并加载最新期望版本，由用户核对后重新提交。
- 用户导入预览绑定不可变行/设置快照，应用阶段使用确认时的任务和预览令牌，并增加卸载世代与轮询互斥。
- 缓存清理、密钥导入、通知预览和流程图 Blob 增加输入世代、卸载失效和资源释放；密钥敏感草稿在关闭和卸载时清理。
- 供应商配置刷新保留 dirty 渠道草稿；系统配置保存后只刷新当前分类，不覆盖其他分类未保存编辑。
- 授权方案重复角色/权限校验改为 `has` 后 `add`；受控发送查看请求改为已注册详情路由及 `id` 参数。
