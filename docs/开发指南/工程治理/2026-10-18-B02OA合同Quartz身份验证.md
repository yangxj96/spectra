# B02 OA 合同 Quartz 身份验证

## 范围与源码复核

本项处理 `CHECK-CORE-034` 的 OA 合同提醒 Quartz 上游调用。CodeGraph 和当前源码确认：`ContractReminderQuartzJob → ContractReminderJob → ContractServiceImpl.sendDueMilestoneReminders` 原来在无用户上下文时对标注 `@DataScope` 的合同执行 `getById`，Framework 会拒绝该 SQL；通知层虽使用了 `OA_CONTRACT_REMINDER` 身份，但任务到不了通知发送。Web 合同页调用 `/api/oa/contract/reminders/run`，按钮要求 `oa:contract:update`；本次 API 路径和请求响应不变。Workflow 通知走独立公共调用方，不在本次修改范围。

Quartz 现在显式调用 Service 的 `sendDueMilestoneRemindersAsSystem(OA_CONTRACT_REMINDER)`。该入口先核对登记的运行身份，再用参数化固定 SQL 仅读未删除合同的 ID、标题、状态和负责人；不创建虚假登录用户，也不全面绕过 DataScope。手动入口在 Service 检查当前有效 `oa:contract:update` 权限，读取合同时继续使用原有 DataScope。两个入口共用到期节点扫描、状态及未删除条件领取、稳定幂等键；失败后的提醒标记重置只匹配本次领取时间。
