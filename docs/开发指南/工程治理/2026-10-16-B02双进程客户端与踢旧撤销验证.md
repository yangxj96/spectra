# B02 双进程客户端与踢旧撤销验证

## 范围与影响

本项为 `BC-BASE-002` 补齐**按客户端与按用户全量撤销**的跨进程证据，以及 **KICK_OLD 并发策略跨进程踢旧**：一个进程执行撤销后，另一进程的旧 Access 被拒绝。后端 CodeGraph 与源码确认：`CacheManagementController` 的 `/admin/security/session/revoke`（按用户+客户端）与 `/admin/security/session/revoke-all`（按用户）调用公共会话撤销端口清理共享 Redis Session；KICK_OLD 由 `KickOldSessionConcurrencyStrategy` 在签发时撤销同端旧会话。两个应用 JVM 共享 PostgreSQL 与 Redis DB 5。本项没有改动端点、协议或生产源码，在 `CoreTwoProcessHttpTest` 增加第二个两进程用例。

## 可观察行为

1. **按客户端撤销跨进程**：第二进程登录的目标用户在首进程经 `/api/cache/admin/security/session/revoke`（`client_type=WEB`）撤销后，其 Access 在第二进程返回 401。
2. **按用户全量撤销跨进程**：重新登录后经 `/api/cache/admin/security/session/revoke-all` 撤销，其 Access 在第二进程返回 401。
3. **KICK_OLD 跨进程踢旧**：Web 策略设为 `KICK_OLD` 时，目标用户在首进程重新登录会踢掉其在第二进程的同端旧会话（旧 Access 401、新 Access 200）。
4. **按在线句柄精确撤销跨进程**：首进程经 `/api/user/online` 列出目标用户在线会话句柄，再经 `/api/cache/admin/security/session/revoke-one`（`session_id`）撤销后，该 Access 在第二进程返回 401。
5. **Access 到期后撤销与 KICK_OLD 跨进程**：Web `access_ttl_seconds=3` 时，第二进程登录的 Access 自然到期后，首进程按客户端撤销使该会话的 **Refresh** 在第二进程返回 401；切换 `KICK_OLD` 后，目标用户在首进程重新登录会跨进程踢掉第二进程同端旧会话（旧 Refresh 第二进程 401、新 Refresh 200）。
