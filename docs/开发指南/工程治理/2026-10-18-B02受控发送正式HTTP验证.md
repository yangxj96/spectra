# B02 受控发送正式 HTTP 验证

## 范围

本项补 `CHECK-CORE-034` 的通知受控发送 Preview/Apply。CodeGraph 与当前源码核对：`NotificationControlledSendController` 的两个 `1.0.0` HTTP 入口分别要求 `notification:send:preview` 和 `notification:send:apply`；Service 将 Preview 绑定操作人、请求摘要和受众解析摘要，Apply 重新解析受众并条件消费 Preview 后由 `NotificationGateway` 入队。Web 的通知发送页经 `NotificationControlledSendApi` 调用这两个入口；本项没有改变请求或响应契约。OA、Workflow 的显式系统身份通知使用另一入口，未由本项运行。

## 实施与实际验证

新增 `NotificationControlledSendFullHttpTest`，只在 `spectra.test.real-deps=true` 下运行。它启动正式应用和 Flyway schema，以随机合成 Root 操作人及收件人执行真实 HTTP：匿名 Preview 不创建记录；有效 Preview 返回一个可发送任务；错误 token 的 Apply 不创建请求；收件人停用后原 Preview 的 Apply 拒绝且不入队；恢复收件人后两个同步起跑的 Apply 只能创建一个逻辑 Request 和一个 Task；再次 Apply 返回幂等重放。测试清理自身 Request、Task、Preview、会话与用户记录。

环境为原生 Windows PowerShell 7.6、mise `test`、JDK 25、项目 Maven Wrapper、专用 PostgreSQL `devops00_spectra_db_test` 与 Redis DB 5。测试入口核对库名和 DB 编号；没有使用真实业务数据或读取本机凭据。
