## 1. 本阶段实现

### 1.1 通知任务与回执

- 新增 `NotificationTaskResultRecorder`：Delivery 插入和 Task 状态迁移在同一事务，使用 `id + PROCESSING + locked_by + locked_at + attempt_count` fence，旧 Worker 不能写入新租约结果。
- 租约超时收敛为 `UNKNOWN`，不自动重发；未领取的 `PENDING/RETRYING` 跨过 `expires_at` 独立收敛为 `EXPIRED`。
- 人工重试保留 `attempt_count`，追加 `max_attempts`，避免历史 Delivery 唯一键冲突。
- Provider 回执仅接受当前 attempt；旧 attempt 或违反终态单调的乱序回执返回 `STALE`，不再清理当前租约或覆盖新结果。
- 地址/敏感载荷密文升级为 `v2:<key_version>:<iv>:<ciphertext>`，按版本读取历史密钥；无版本 `v1` 旧密文先尝试 ACTIVE，再受限尝试历史版本。
- HTTP JSON Provider 使用 `NotificationTaskMessage` 发送解密后的标题、正文和参数；腾讯云不再显式设置 JDK 受限 `Host`，健康检查读取嵌套 `Response.Error`。
- Provider 健康快照增加有效期（默认 300 秒），过期、配置变化或重启后发送前重新检查，失败保持 fail-closed。

### 1.2 共享运行任务

- Quartz `abandonExpired` 最终更新增加 `target.status = 'RUNNING'`，不覆盖已成功终态。
- 用户导入 Apply 在事务提交后派发，最终状态使用 `status=APPLYING + operator_id` CAS；新增 `user.import.apply-recovery` 每分钟按心跳恢复超时任务。
- 诊断任务创建使用 PostgreSQL advisory lock 串行化全局预算，提交后派发；执行前 `PENDING → RUNNING` 原子领取，清理作业每分钟恢复遗留 PENDING、收敛超时 RUNNING，并只在文件删除成功后删除元数据。
- 缓存操作 ID 绑定规范化意图，成功回执复用，`FAILED/PARTIAL` 可在同意图下重试，回执保留 1 小时且有容量上限。
- 告警规则修改改为 Service 事务，在途评估重新校验规则版本/启用状态，通知受理后回执写入失败不回滚已受理通知。

### 5.1 实现

- 新增 `V10__service_monitor_diagnostic_instance.sql`：`sys_service_monitor_diagnostic_task` 增加 `instance_id` 及 `(instance_id, status, requested_at DESC)` 索引；历史行回填 `unknown`。
