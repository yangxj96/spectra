# B02 绑定验证码预算正式 HTTP 验证

## 范围与影响

本项为 `CHECK-CORE-023`（`DIAG-CORE-023`）补齐**真实 HTTP** 证据：认证身份绑定验证码按地址键与用户绑定，验证码核验在同一原子操作内累计尝试并在耗尽时使验证码失效。后端 CodeGraph 与源码确认：`AuthenticationIdentityBindingServiceImpl.consumeBindingCode` 使用 `key = BIND_EMAIL_CODE + address`、`expected = userId + ":" + digest(code, hmac)`，调用 `RedisSecurityVerificationStore.consumeWithinAttemptBudget(key, key + ":attempts", expected, maxAttempts)`；Lua 脚本先比对 owner、再累计 attempts，达到上限即删除验证码与尝试键并返回耗尽。本项没有改动端点、响应字段或生产源码。

测试通过正式 `/api/security/identities/email`，在专用 PostgreSQL/Redis 上插入真实 PASSWORD 身份与 ROLE_DEV_OPS 授权并登录；由于自定义部署要求密钥管理，用例以 `--spectra.security.secret.master-key` 启动并创建、发布 `security.verification-code-hmac` 后再播种绑定验证码。

## 可观察行为

1. **预算内成功**：错误验证码尝试 `maxAttempts-1` 次后，正确验证码在第 `maxAttempts` 次核验成功（200），并在 `sec_authentication_identity` 落库 EMAIL 身份。
2. **原子耗尽**：错误验证码尝试 `maxAttempts` 次后，验证码键被原子删除；随后即使提交正确验证码也返回 400，应用日志出现「绑定验证码尝试次数过多」。
3. **按地址绑定**：把为地址 C 播种的验证码提交到地址 D，返回 400，且不消耗地址 C 的预算；随后地址 C 的正确验证码仍可绑定成功。
