# B02 CHECK-CORE-034 授权后台调用方整体验证

## 范围与实现

- 按 Core、Workflow、OA 和 Launch 的 CodeGraph 调用链及当前源码复核：通知受控发送、公开 Assignment/角色定义变更、Workflow 任务四写动作、OA 审批回调、合同提醒 Quartz 与通知 Worker。Web 保持既有 `1.0.0` 受控发送和 Workflow 任务 API；本轮没有改变请求或响应协议。
- Workflow 四写动作在同一业务事务中，先经 `AuthorizationMutationFence` 锁住操作者的 `sys_user` 行，再读取有效授权快照和修改 Flowable 任务。Core 的 JDBC 实现复用角色、Assignment 写入的用户行锁顺序；无事务、用户不存在或数据库锁失败直接拒绝或传播失败。
- 锁实现还检查锁住用户的状态必须为 `ACTIVE`，已停用用户不能凭旧主体直接调用 Workflow 写入。
- 受控发送沿用已实现的用户行锁、有效授权快照、Preview 一次消费和统一 Gateway；本轮补充反向提交顺序、跨 JVM 缩权竞争及数据库中途故障测试。没有新增兼容入口。
- OA 请假、采购、报销的通过、驳回、终止回调复核明确申请人受众及重放语义；合同提醒和通知 Worker 在同主机两个独立应用 JVM 上共享 Quartz、PostgreSQL 与 Redis。

## 验收边界

- 本机只有一个测试主机。用户于 2026-10-26 明确表示无第二台测试主机，并要求将跨主机环节作为本检查的定点验收例外。真实跨主机同业务键、单端网络故障未运行；上述双实例均是同一 Windows 主机上的独立 JVM，共享专用测试 PostgreSQL/Redis。
- 本轮使用 IN_APP 与 MOCK 链路，未声称外部邮件供应商实发。真实 Provider 验收不属于本检查显式后台身份和授权核心的通过依据。
- CHECK-CORE-019 的 DataScope 后台拒绝、CHECK-CORE-032 的角色快照与重登录分别有其独立正式证据；本轮只复核其对 Workflow/OA/通知公共调用方的适用性。B08 Web 身份失效保持独立治理。
- 本检查通过不推定 B02 批次或集中治理周期完成。
