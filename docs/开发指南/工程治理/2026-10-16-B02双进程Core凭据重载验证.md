# B02 双进程 Core 凭据重载验证

## 范围与影响

本项为 `CHECK-CORE-022`（`DIAG-CORE-022`）补齐**两个独立应用 JVM 的正式 Core 凭据重载**证据，并作为 `BC-BASE-002` 改密入口跨进程与 `CHECK-CORE-019/032` 两进程专项的共同前置套件。后端 CodeGraph 与源码确认：改密经 `/api/user/password` 在业务事务内更新 `sec_password_credential` 并调用公共会话撤销端口清理 Redis Session；两个应用 JVM 各持自己的 Spring 上下文，但读写同一 PostgreSQL 与 Redis DB 5。本项没有改动端点、响应字段或生产源码，新增 `CoreTwoProcessHttpTest` 使用真实 Core 身份（正式登录）而非合成身份。

## 可观察行为

1. **跨进程签发可见**：在首进程用正式 Core 用户登录，其 Access 在第二进程的 `/api/security/context` 返回 200。
2. **改密跨进程撤销**：在首进程改密成功后，旧 Access 在首进程与第二进程都返回 401；旧 Refresh 在第二进程刷新返回 401。
3. **新凭据跨进程重载**：改密后，第二进程用新口令登录正式端点返回 200。
4. **Access 自然失效跨进程重载**：Web `access_ttl_seconds` 收紧到 2 秒时，第二进程登录的 Access Redis Key 自然到期后，两端访问 `/api/security/context` 都返回 401；仍有效的 Web Refresh 可在首进程轮换出新 Access，新 Access 在第二进程返回 200。
