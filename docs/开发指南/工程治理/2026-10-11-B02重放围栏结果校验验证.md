# B02 BASE-004 重放围栏结果校验与当前版验证

## 范围与处置

本次只处理 `DIAG-BASE-004`，复核 `IMP-BASE-003` 和 `BC-BASE-001`。2026-10-09 已用 Redis Lua 原子执行 Refresh claim、用户索引确认与重放 Family 围栏，并在签发及 Reader 边界拒绝围栏后的会话。当前源码复核发现 `claim` 将 Lua 的 `Long` 返回值转成 `int` 后判定，异常值 `4294967297` 会折叠成成功状态 `1`；安装围栏只要求返回非 `null`，映射清理将未知返回值当作普通未匹配。这些结果均不能证明安全状态，现改为只接受各脚本定义的精确返回值，其他值抛出 `SecurityRedisUnavailableException`。

直接调用方为 Framework 的 Refresh、Session 签发、撤销和 Reader；Core 的 `LoginServiceImpl.refresh` 经正式认证端口复用该链路，`AuthenticationController` 负责 HTTP Cookie 与 CSRF。OA/Workflow 没有直接调用 Refresh 端口，但共用 Framework 认证边界。Web `AuthApi.refresh` 的路径、Cookie 和响应形状未变，`auth.ts` 在刷新失败后清理本地会话；页面级身份切换与浏览器行为仍归 B08。本次无需修改这些调用方代码。
