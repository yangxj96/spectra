# B02 改密审计正式 HTTP 验证

## 范围与影响

本项为 `BC-BASE-005`（`DIAG-BASE-001`）补齐**真实 HTTP 与正式审计表**证据：通过 `/api/user/password` 改密时，`@Audit` 切面把业务与成功审计写入同一事务，且正式表 `spectra_core.sys_audit_event` 的 `before_snapshot` 已按统一规则脱敏口令。后端 CodeGraph 与源码确认：`AuditAspect` 默认 `captureArguments=true`，`before` 快照包含方法入参（`ChangePasswordFrom` 的 `oldPassword/newPassword/verifyPassword`）；`JacksonAuditSanitizer` 先按 JSON 字段展开，再交 `DefaultAuditSanitizer` 屏蔽以 password/token/secret 等结尾的字段为 `***`。本项没有改动端点、响应字段或生产源码。

## 可观察行为

1. **同事务且可查**：认证用户改密返回 200 后，正式审计表按 `X-Correlation-ID` 能查到 `event_type` 以 `#changePassword` 结尾、`result=SUCCEEDED` 的审计行（与业务在同一事务提交）。
2. **入参脱敏**：该行 `before_snapshot::text` 含统一脱敏标记 `***`；旧口令与新口令的明文都不出现在 `before_snapshot`、`after_snapshot`、`reason`、`failure_reason` 中。
3. **业务生效**：改密后旧口令登录 401、新口令登录 200。
