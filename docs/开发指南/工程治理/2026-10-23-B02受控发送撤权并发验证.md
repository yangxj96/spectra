# B02 受控发送 Assignment 撤权并发验证

## 范围与实现

本项核对 `DIAG-CORE-034`、`IMP-CORE-007`、`CHECK-CORE-034` 的受控发送 Apply 与操作人 Assignment 撤权竞争。CodeGraph 和源码核对：受控发送公开调用方是 Core Controller 与 Web 管理页；OA、Workflow 后台通知使用公共通知端口，不调用此 Service。Assignment 撤权在事务中锁目标 `sys_user` 行，修改授权、推进安全版本并撤销 Session。原 Apply 在权限快照读取前不锁此行，撤权可在授权检查后、入队提交前生效。

Apply 现在在同一数据库事务中先锁操作人有效用户行，再读取实时权限快照、消费 Preview 和入队，锁保持至提交。无法读取有效用户行或加锁失败时拒绝，不将故障当作仍有权限。Preview 原有短时快照和数据范围重算继续执行。

## 验证边界

本项的竞争事务用专用库中的合成 Assignment SQL 模拟正式撤权的用户行锁和授权失效顺序；没有通过公开撤权 Service/HTTP 并发执行，也没有覆盖角色定义整体缩权与 Apply 的竞争。两个独立应用 JVM 消费同一 Preview 已单独验证；真实跨主机网络和其他后台故障仍未验证。`CHECK-CORE-034` 和 B02 保持进行中。
