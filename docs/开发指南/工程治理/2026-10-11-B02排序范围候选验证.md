# B02 BC-BASE-008 排序与范围候选验证

## 本次范围与源码复核

此前 `BC-BASE-008-SORT` 已记录 32 个分页入口的字段映射复核、恶意排序表达式拒绝和 86 项定点测试。本次只处理尚未运行的 `BC-BASE-008-SCOPE`。CodeGraph 与当前源码核对 `DataScopeInnerInterceptor.getSqlSegment`、`ScopeSqlPolicy.permissionFor/build/relationSubquery` 及 Core、OA、Workflow 的受影响表。Framework 的 `ScopeSqlPolicy.permissionFor` 原先对 Mapper 方法名只要包含 `insert/create/add` 就返回 `null`，使 `selectAdditionalRows` 和 `updateAddress` 这类名称跳过数据范围；关系维度的 `mainColumn` 未限定主表别名，在联表出现同名列时生成歧义 SQL。此次合成测试先复现两类缺陷，再修复。

现在进入数据权限拦截器的受保护查询、更新和删除不因 Mapper 名称中的这些子串跳过范围；已核对本地 MyBatis-Plus 3.5.15 `DataPermissionInterceptor` 的实际字节码，`beforeQuery` 处理查询，`beforePrepare` 只处理 UPDATE/DELETE，不处理 INSERT。关系子查询的外层列使用当前主表的别名。无快照 Boundary 时的查询与更新仍生成 `1 = 0`。移除了拦截器中因此变得不可达的 `permission == null` 分支。

关系维度当前用于 OA 会议与采购收货实体，Core 和 Workflow 没有直接声明 `@DataScope.Relation` 的实体；这些调用方继续使用相同的拦截器，无请求协议或 Web 排序字段变化。当前 Mapper 精确搜索未找到名称匹配本次误跳过样例的生产方法，因此本次不推断已有实际越权。OA/Workflow 的独立业务治理不在本单项任务内。

真实 PostgreSQL 测试验证了带同名 `id` 列的主表与联表下，只返回主体有关系授权的合成行；拦截器入口测试验证缺少 Boundary 时查询和更新均拒绝。它们没有运行 OA 会议/采购的完整 Mapper、Spring HTTP、真实业务 schema 或浏览器路径。`RegionServiceTest` 在完整门禁中显式排除。`BC-BASE-008-SCOPE` 的候选检查已通过；`BC-BASE-008` 整体仍受全部业务入口的真实 HTTP/schema 证据限制，B02 的其他行为检查也未全部完成。
