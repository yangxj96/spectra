# B02 受控发送跨实例消费验证

## 范围

本项补 `DIAG-CORE-034`、`CHECK-CORE-034` 和 `IMP-CORE-007` 的受控发送跨实例消费证据。`NotificationControlledSendController` 的 Preview/Apply 由 Core Service 执行最终授权，Apply 以数据库条件更新消费 Preview，再通过通知网关入队。测试在两个独立应用 JVM 共享专用 PostgreSQL 与 Redis 时，使用合成 Root 操作者和收件人，通过正式 HTTP 并发提交同一 Preview。

两个 JVM 的请求同时释放；至少一个 Apply 成功，双方均不得返回服务端错误。共享数据库最终仅有一条对应 `ntf_request` 和一条 `ntf_task`，第二实例再次 Apply 返回幂等重放标记，逻辑请求数仍为一。原有同进程并发、错误 Token、受众变化、角色到期和 Service 最终授权断言继续执行。测试数据按请求键和操作者清理，站内信先于任务删除。

## 实际执行

环境：原生 Windows PowerShell、`mise -E test exec --`、JDK 25、后端 Maven Wrapper、正式 Flyway schema、专用 `devops00_spectra_db_test` 和 Redis DB 5。两个进程有不同 PID；使用合成随机用户和请求键，未读取或输出本机凭据。日志存于 `.temp/b02/`，不纳入 Git。

## 验收边界

本项验证同主机两个独立应用 JVM 对同一 Preview 的竞争消费及幂等重放。它不验证真实跨主机网络、外部供应商投递、受控发送与角色变更同时竞争，也不替代 `CHECK-CORE-034` 中 OA 回调、Quartz 和 Workflow 任务的其他故障场景。`CHECK-CORE-034` 与 B02 仍保持进行中。
