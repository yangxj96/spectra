# 前端页面与业务模块

> 本页根据 `spectra-ui/src/views/`、`src/plugin/router/modules/` 和 `src/api/` 的当前代码整理。页面文件以 `index.vue` 为主入口，页面专属组件放在同级 `components/`。

当前 `src/views/` 下有 100 个 Vue 页面文件（包含页面专属子组件）；新增页面必须同步路由、菜单权限和 API 文档，不能只添加一个孤立的 Vue 文件。

## 通用页面结构

管理列表页通常由以下部分组成：

```text
页面 index.vue
  ├─ 查询条件 / 表单
  ├─ 操作栏（v-permission 控制按钮）
  ├─ ElTable / 分页
  ├─ 详情、创建或编辑子组件
  ├─ useTable 或页面本地 loading 状态
  └─ 领域 Api 模块
```

编辑页和详情页通常通过 query、route params 或父页面状态取得 ID。返回列表时使用具名路由或明确的 `path + query`，不要依赖浏览器历史栈中不稳定的页面状态。

异步预览、导入、刷新和编辑授权按输入世代或请求序号丢弃迟到响应；保存识别 HTTP 409 时保留草稿、提示最新版本，核对后采用新版本重新提交。部门合并/拆分修改选择或表单会清除旧预览，过期或冲突需重新预览；批量导入的 Preview 绑定不可变快照与令牌；配置刷新保留 dirty 草稿；用户编辑页的授权编辑器在编辑期间保持挂载。

## 系统管理

系统管理页面集中在 `src/views/System/`：

- 用户管理支持新增、编辑和批量导入；导入分为预览和应用两个阶段，失败行会展示分类后的错误信息。
- RBAC 页面管理角色、授权方案和菜单，授权方案用于把权限目录映射到角色或用户范围。
- 部门管理 `/system/dept` 提供部门维护，列表不提供行选择框或行级拆分操作；“部门合并”和“部门拆分”入口位于“新增”之后。同级部门合并 `/system/dept/merge` 与直属成员拆分 `/system/dept/split` 使用独立三栏步骤页，左侧导航步骤、中间填写资料和预览影响、右侧说明规则。两页第一步均选择源部门；合并后选择至少两个同级部门，拆分后选择直属成员并保留跨页选择，提交前均重新预览并二次确认。
- 字典、菜单和行政区划是其他页面共享的基础数据入口。
- 用户、个人资料、菜单、字典、行政区划、系统配置和 Quartz Job 编辑提交携带 `version`；版本不满足时后端返回 `ENTITY_UPDATE_CONFLICT` / HTTP 409，页面保留草稿。行政区划编辑入口通过 `GET /api/region/{id}` 读取版本；用户编辑不提交手机号或邮箱修改。
- 菜单删除在存在活动子节点时被拒绝；用户批量删除先全量校验目标和权限，任一无权限或不存在 ID 都整体失败，不部分成功。
- 管理接口在 Service 层执行最终 `@PreAuthorize`，越权返回 HTTP 403 `ACCESS_DENIED`；页面按钮和路由守卫只控制交互入口，不构成授权依据。
- 工作流页面提供流程定义管理；流程定义编辑页由 LogicFlow 和 Flowable 插件提供。

按钮级权限使用 `v-permission`，例如 `user:create`、`menu:update`、`workflow:task:update`。页面可见性只是交互层控制，API 仍须接受后端鉴权结果。

## OA 业务页面

OA 页面位于 `src/views/OA/`，业务 API 位于 `src/api/oa/`：

| 页面 | 主要状态和动作 |
|---|---|
| 请假 | 草稿、提交、撤回、取消；选择审批人并关联工作流 |
| 费用报销 | 明细、附件、审批、撤回、取消和付款 |
| 采购申请 | 申请、审批、执行登记、分批收货，并可转资产 |
| 资产管理 | 台账、分类、领用、归还、调拨、维修、报废 |
| 办公用品 | SKU、库存入库、领用、退库、调整和低库存 |
| 合同 | 版本、履约节点、签署、激活、终止、归档和提醒 |
| 文档 | 目录、版本、发布、归档和当前版本切换 |
| 会议/日历/公告 | 创建、邀请响应、签到、日程和公告已读/撤回 |
| 审批中心 | 待办/已办、业务详情、同意和驳回，按流程定义 Key 过滤 |

附件业务只保存后端返回的 `file_asset_id`，上传过程统一使用 `useFileUpload`；业务页面不保存浏览器 File 对象作为服务端事实。

## 工作流页面

`src/views/System/Workflow/` 下有两个边界清晰的页面能力：

- `index.vue`：展示流程定义列表。
- `components/WorkflowDesigner/`：创建或编辑 BPMN 流程，读取流程资源 XML，调用 Flowable 插件导出并部署。

工作流编辑器通过 query 中的 `id` 判断编辑模式，通过 `key` 传递部署 Key。具体画布、Picker、XML 和部署流程见 [[07-Spectra宿主集成]]。

## 通知和运维页面

通知中心是当前用户视角，入口 `/notification` 是静态认证路由，不写入数据库菜单；头部 `NotificationBell` 复用同一 Notification Store。通知运维是管理员视角，路由集中在 `src/plugin/router/modules/devops.ts`，包括：

- 概览：渠道状态、队列、失败/UNKNOWN 指标和投递趋势。
- 请求/任务/投递：分页、详情、脱敏错误、任务重试和取消。
- 模板：逻辑模板组、渠道草稿、版本、预览、发布、归档和对比；版本历史按固定版本号倒序分页，不接受客户端排序，每页限制 1–100。
- 渠道：IN_APP、SMS、EMAIL 配置、健康检查和明确确认词后的测试发送。
- 通知发送：模板占位符渲染后同步发送；短信/邮箱只使用当前激活配置。

运维页面不能用模拟数据掩盖后端未接入能力；未接入真实接口的预定义路由应保持 Placeholder 并在文档中明确状态。

## API 模块分布

当前 API 封装按领域拆分：

```text
src/api/
├── auth/             认证、角色、授权、安全上下文和审计
├── authentication/   身份认证辅助接口
├── user/             用户、部门和用户导入
├── system/           初始化、字典、菜单、文件、区域、调度、监控、密钥
├── workflow/         流程任务和流程定义
└── notification/     消息、模板、渠道配置和发送历史
└── oa/               OA 各业务模块
```

API 模块只做路径、参数和返回类型映射，不在其中编写页面状态、弹窗或路由跳转。页面负责 loading、表单校验和成功后的刷新，后端负责最终业务校验。

## 页面新增检查表

- 是否放在正确的 `src/views/{模块}/{页面名}/index.vue` 目录？
- 是否加入正确的路由模块，并设置 `requiredMenu` / `activeMenu`？
- 是否补充后端菜单、权限编码和前端 `v-permission`？
- API 是否位于正确领域目录，并使用统一请求客户端？
- 分页、空状态、错误状态和重复提交是否处理？
- 文件、消息、流程等跨模块能力是否复用已有组件或服务？
- 是否增加页面/API 测试，并更新本页矩阵？
