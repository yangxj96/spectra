# Core 统一通知子域

`core.notification` 是 `spectra-core` 内置的同步通知子域，包名为
`com.devops00.spectra.core.notification`，由 `CoreModule` 统一扫描。业务模块通过
`spectra-common.notification.NotificationService` 发送通知，不直接写通知表或依赖渠道实现。

## 当前边界

- 通知表统一位于 `spectra_core` schema，表前缀为 `ntf_`。
- `ntf_template` 保存模板，按 `(code, channel)` 唯一；支持内置模板和启停。
- `ntf_message` 保存发送历史；站内信记录同时作为用户收件箱，`read_at` 为空表示未读。
- `ntf_sms_config` 和 `ntf_email_config` 保存多渠道配置；同一表最多一条 `active` 配置。
- 未配置或未启用外部渠道时发送失败并记录历史，不回退到其他配置。
- 站内信无需配置，直接写入 `ntf_message`。
- 内置 MOCK 短信/邮箱配置随 V1 种子创建，开发环境可直接验证发送链路。

## 同步发送链路

1. 业务模块构造 `NotificationSendRequest`，提供模板编码、渠道、收件人和模板参数。
2. `NotificationServiceImpl` 校验请求并按 `(code, channel)` 加载启用中的模板。
3. `NotificationTemplateRenderer` 执行 `{{name}}` 占位符替换；缺少参数时拒绝发送。
4. 用户收件人由 `NotificationRecipientDirectory` 解析为手机号/邮箱；直接地址用于验证码等未登录场景。
5. 对应渠道的 `NotificationSender` 同步发送：
   - `IN_APP` 由通知服务写入 `ntf_message`。
   - `SMS` 使用当前启用的短信配置，支持 ALIYUN、TENCENT 和 MOCK。
   - `EMAIL` 使用当前启用的邮件配置，支持 SMTP 和 MOCK。
6. 每个收件人×渠道结果写入 `ntf_message`，返回逐目标回执。

发送失败不重试、不补发；调用方根据回执决定是否补偿。验证码在发送失败时删除 Redis 验证码并抛出异常。

## 模板

- 模板字段：`code`、`name`、`channel`、`title_template`、`content_template`、`html_template`、`provider_template_code`、`builtin`、`enabled`。
- 站内信和短信使用纯文本正文；邮件可使用 HTML 正文。
- 内置模板由 V1 种子维护，覆盖安全验证码、Workflow、OA 和系统通知。
- 管理端可新增、修改、启用/停用模板；内置模板不能删除。

## 配置

- 短信配置：`name`、`provider`、`access_key_id`、`access_key_secret`、`sign_name`、`provider_template_code`、`region`、`extra`、`active`。
- 邮件配置：`name`、`provider`、`host`、`port`、`username`、`password`、`from_address`、`from_name`、`ssl_mode`、`extra`、`active`。
- 腾讯云短信的 `appId`、`templateParameterOrder` 等供应商扩展字段放入 `extra`。
- 配置凭据按当前简化约定明文存储；仅管理端可见，后续如需要可单独增加加密列。

## 收件箱与历史

- 当前用户收件箱继续使用 `/notification/**`：列表、详情、未读数、已读、全部已读、删除、批量删除。
- 管理端历史使用 `/notification/admin/messages/page` 和 `/notification/admin/messages/{id}`。
- 管理端模板使用 `/notification/admin/templates/**`。
- 管理端短信配置使用 `/notification/admin/sms-configs/**`，邮件配置使用 `/notification/admin/email-configs/**`。

## 跨模块调用

- Security 验证码、OA 公告/会议/文档/合同提醒/申请状态、Workflow 待办与结果、服务监控告警均通过 `NotificationService`。
- 跨模块只依赖 `spectra-common.notification` 的接口和值对象，不引用 Core 内部 Entity、Mapper 或实现类。
- `NotificationCounter` 提供跨模块未读数读取，由 Core 适配到站内信历史。

## 已移除能力

- 通知 Request/Task/Delivery 异步投递、Worker、Quartz 通知任务和重试退避。
- Provider 健康检查、回执回调、测试发送接口。
- 受控发送 Preview/Apply、用户通知偏好、免打扰、模板版本和发布状态。
- `NotificationPurpose`、`NotificationSystemActor`、`NotificationGateway` 和 `NotificationRequest`。

## 迁移说明

- V1 基线已直接改写为 4 张 `spectra_core.ntf_*` 表，并删除 `spectra_notification` schema。
- 已有开发库需要重建；生产环境升级需另行设计一次性迁移。
- 模板、配置和历史文档以本页、实体清单和 API 总览为准。
