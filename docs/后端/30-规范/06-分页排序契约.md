# 分页排序契约

## 输入与失败语义

API 版本保持 `1.0.0`。请求使用 `PageFrom.orders: List<PageOrderFrom>`，每项包含 `column: string`、`asc: boolean`（默认 true）。HTTP 查询参数绑定示例：`orders[0].column=id&orders[0].asc=false`。

`PageOrderFrom` 保留原始字段值，不使用 MyBatis `OrderItem` 的输入清理；例如 `id--`、`i d`、` id ` 必须拒绝，不能被清理成已登记的 `id`。SQL 分页使用 `PageFrom.toPage(allowedSortFields)`；服务端将公开字段映射为可信列名后创建新的 `OrderItem`。原请求列表或项的后续修改不影响已生成的分页对象。

以下输入返回 HTTP 400，消息固定为“**不支持的分页排序字段**”：未登记字段、敏感列、表达式、客户端表别名、空/null 字段、null 排序项、重复目标列。异常不回显恶意输入。服务端映射缺失或包含非法 SQL 列表达式属于配置失败，同样不会执行该查询。

`orders=null` 和空集合都不追加排序，保留原查询的默认排序。合法自定义排序由 MyBatis 分页插件追加到原有排序前面，原默认排序仍可作为后续比较条件。排序输入不是授权信息；各用例原有授权和数据范围仍然生效。

## 固定排序入口

## 调用方与验证

Web `BasePageParams.orders?: OrderItem[]` 的字段形状与后端一致；当前页面不发送自定义 `orders`。

分页入口统一拒绝未知字段、恶意表达式、未登记字段和固定排序入口的非空排序；SQL 调用方显式声明公开字段到可信列名的映射，转换结果不受原请求列表后续修改影响。OA 通讯录和 Workflow 固定排序入口按各自业务授权与范围执行。

排序字段白名单由每个分页用例显式登记；范围 SQL 对查询、更新和计数应用同一数据范围规则。Web 不发送自定义排序，固定排序入口拒绝非空 `orders`。
